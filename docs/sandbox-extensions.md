# 沙箱扩展

在「配置 → 沙箱扩展」保存创建沙箱时运行的安装和验证脚本。管理页默认使用列表，也可切换卡片；名称、标识和说明可搜索，来源与启用状态可筛选。

## 使用

1. 新建扩展，只需填写名称、安装命令和验证命令。标识自动生成；版本标签默认 `1.0.0`，超时默认 600 秒。需要调整时展开「高级设置」，也可在那里关闭「启用扩展」保存未完成的配置。
2. 在沙箱模板中选择默认扩展，或在创建沙箱时调整选择。搜索和切换「已选」不会丢失已有选择。最多选择 64 个，按选择顺序逐个安装和验证。
3. Worker 完成安装并验证成功后，沙箱才会就绪。沙箱详情展示每个扩展的状态、耗时和经过脱敏的输出。

扩展需要更新后的 Worker，服务器须上报 `sandbox-extensions` 能力。未更新的 Worker 仍可创建不带扩展的沙箱，但不能接收扩展安装任务。

## 脚本约定

- 脚本在沙箱内以 root 身份运行，工作目录使用沙箱配置的工作目录。只使用可信脚本。
- 沙箱镜像必须提供 `sh`、`mktemp` 和 GNU coreutils 的 `timeout`。脚本按 `sh -eu` 执行，需要 Bash 的命令应显式调用 Bash。
- 安装和验证分别受超时限制，每一步默认 600 秒，可设置 30–1800 秒。任一步退出码非零或超时都会使创建失败。
- 安装与验证脚本各不超过 64 KiB。版本字段用于记录，不会自动替换脚本中的包版本；需要可重复安装时应在脚本中固定版本。
- 勾选「需要网络」的扩展不能用于完全隔离网络的沙箱。关闭该选项只表示扩展不依赖网络，不会放宽沙箱的网络策略。
- 凭据通过已有的加密沙箱环境变量配置注入，不要写入扩展定义，也不要让脚本打印密钥。输出会过滤已知注入值及常见编码形式，但无法识别脚本自行生成或变形的所有敏感数据。
- 每个扩展的原始输出上限为 1 MiB；达到上限会中止并隐藏该日志，避免泄漏截断的密钥。页面仅显示最多 4 KiB 的脱敏尾部输出。
- 「预设」只是来源标记，不代表经过安全审核；当前没有内置 Multica 安装配方。可用同样的表单配置所需软件的安装命令。

先用一个无网络依赖的小扩展确认环境：

```sh
# 安装脚本
printf 'ready\n' > /workspace/extension-ready
```

```sh
# 验证脚本
test "$(cat /workspace/extension-ready)" = ready
```

## 已有沙箱与失败处理

创建时会固定所选扩展的名称、版本、generation 和脚本。之后修改扩展或模板，只影响新建沙箱。已有沙箱的编辑、启动与重启不会重跑安装，也不会继承模板后来增加的扩展。

扩展失败后按现有创建失败流程清理本次新建实例。不要依赖启动操作来重试安装；修正配置后创建一个新沙箱。被模板或沙箱引用的扩展不能删除，可以停用，阻止新建沙箱继续选择它。

此功能只负责创建时安装与验证，不负责后台服务守护、自动升级、卸载或向运行中的沙箱追加安装。
